# 从 3D 实验台到教育平台：可行性、合规与路线

> 结论先说：**技术上都能做**，但"小程序 / 安卓 / 平台"是三件不同难度的事。
> 建议按「Android APK + 网页版（现在就能用）→ 单知识点小程序（获客/课堂入口）→ 教育平台 MVP（账号/班级/作业）」三级推进，
> 每一级都用真实师生反馈作为进入下一级的门槛，而不是先堆功能。

---

## 0. 四条落地路径对比

| 路径 | 工作量（相对现状） | 关键门槛 | 建议阶段 |
| --- | --- | --- | --- |
| **网页 / PWA** | 极低（已有移动端布局） | 需要 HTTPS 域名（国内需 ICP 备案）；微信内置浏览器兼容性 | 现在就能发链接 |
| **Android APK** | 低（✅ 已产出，229 KB） | 上架需 release 签名、软著、隐私政策、应用商店审核、教育类备案 | 现在就能发给朋友/学生 |
| **微信小程序** | 中高（UI 需重写、3D 适配、分包） | 主体与类目资质、审核、包体积、低端机 WebGL 性能 | 第 2 阶段做"轻量入口" |
| **教育平台** | 高（3–6 人月起步） | ICP + 教育移动应用备案 + 等保（视客户）+ 内容审核 + 持续运营 | 有试点学校/付费意愿后再做 |

## 1. 微信小程序：能做，但不是"把 HTML 传上去"

### 1.1 技术现实

- 小程序**不是浏览器**：没有 DOM、没有 CSS 布局引擎，当前基于 HTML/CSS 的三栏面板需要改成 **WXML/WXSS**（或把 UI 画进 canvas）。
- 3D 部分可以复用：小程序支持 `<canvas type="webgl">`，通过 **threejs-miniprogram / three-platformize** 等适配层跑 three.js；材质、光照、几何体基本可复用。
- 本项目代码复用度粗估：
  - 物理模型 / 逻辑模型 / CPU 仿真：**~100% 复用**（纯 JS，无 DOM）
  - three.js 场景搭建：**~80% 复用**（渲染器替换、触摸控制、标签投影改到 WXML 覆盖层或 canvas 2D）
  - 2D 电路图（Canvas 2D）：**~90% 复用**
  - 左右教学面板（HTML/CSS）：**基本重写**
- 包体积：微信对主包/分包有大小限制（主包约 2 MB 级、整包约 20 MB 级，**以官方最新文档为准**）。当前单文件 705 KB 可作为一个分包放下，但加上更多课程内容要规划分包与懒加载。
- 性能：低端机上 WebGL + 粒子系统要降级（减少粒子、限制 DPR、关闭阴影/抗锯齿）。

### 1.2 资质与审核

- 小程序需要**注册主体**（个人/企业/学校），选择服务类目；教育相关内容审核更严格，涉及课程/培训可能要求资质。
- 若联网（账号、数据、内容分发）：需要**域名 + ICP 备案 + HTTPS + 隐私政策**；涉及未成年人信息要额外谨慎。
- 审核对"教育"类目的口径经常变化，**以微信公众平台最新规则为准**，上线前预留 2–4 周审核/整改时间。

### 1.3 建议做法

**不要把四层完整工作台一次性搬进小程序。** 第一版只做"单知识点小程序"：

- 例如只做 **L4 存储程序计算机**：一个 3D 加法器/CPU 单步场景 + 3 道选择题 + 分享卡片；
- 扫码即用、无需下载，适合课堂提问、家长转发、公众号引流；
- 完整工作台继续留在网页/APK 里（信息密度大，需要大屏）。

## 2. Android：已经做出来了

- 现状：`android/out/Triode2Computer-0.1.0.apk`，229 KB，WebView + 离线资源，横屏沉浸式，无网络权限。
- 技术路线：**WebView 壳**，一份 HTML 同时服务桌面浏览器、手机浏览器和 Android App；不做原生重写，维护成本最低。
- 分发：
  - 直接发 APK：适合朋友/小范围教学（需允许"未知来源"）；
  - 应用商店：必须换 **release 签名**，准备软著、隐私政策、截图与描述、教育类备案材料。
- 微信内不能直接安装 APK（微信不允许），需要"用浏览器打开下载"。

详见 `安卓版说明.md`。

---

## 3. 手机网页 / PWA（最被低估的一步）

- 现有产物已经做了移动端布局：3D 全屏 + 底部「控制台/仪表」抽屉，手机横屏体验可用。
- 把 `index.html` 放到任意 HTTPS 静态托管（国内需备案域名）即可发链接；微信内打开可能需要提示"用浏览器打开"以获得完整 WebGL 性能。
- 适合：课堂投屏、家长群发链接、公开课 demo、快速验证需求。
- 加上 manifest + service worker 后可"添加到主屏幕"，接近 App 体验；但离线缓存仍要求 HTTPS。

## 4. 教育平台：真正的产品形态

### 4.1 先定方向（决定合规和销售）

- **B 端（学校/机构）**：一班一码、教师端、作业与学情、私有部署/等保、按年授权。
- **C 端（家长/学生）**：微信/手机号登录、课程包订阅、练习闯关、分享裂变。
- 两者产品、合规、销售完全不同；**不要同时做**。

### 4.2 平台 MVP 功能清单（建议 2–3 个月）

必须有：
- 内容：4 个场景 + 每层 3–5 道题（选择/填空/操作题可先做选择与参数判断）+ 教师手册
- 账号：微信登录 / 手机号；学生、教师、班级三种角色
- 班级与作业：教师建班、发作业、看完成率；学生提交、自动判分
- 学情：每层完成度、错题分布、平均用时
- 分享：二维码/链接进入指定场景（可带参数）
- 后台：内容管理、用户管理、基础数据看板

先不做：
- 支付、复杂社交、AI 批改、直播、多课程商城、原生 App 双端

### 4.3 技术架构（在现有项目上扩展）

```
Web / PWA（当前 three.js 项目，复用）
        │
API 服务（Node/NestJS 或 Supabase/Firebase，视国内合规选择）
        │
PostgreSQL + 对象存储（课件/截图）
        │
管理后台（React 或现成 low-code）
        │
微信小程序（第二阶段，作为轻量学生端入口）
```

- 前端复用当前 `src/`；把场景参数化（`?lesson=L4&step=3`），便于"课程包"驱动。
- 埋点先做最小集：进入场景、操作次数、完成、测验正确率。

### 4.4 合规清单（中国，重要）

| 事项 | 说明 |
| --- | --- |
| ICP 备案 | 有服务器/域名就要做，周期约 1–3 周 |
| 教育移动互联网应用程序备案 | 面向教育的 App/小程序通常需要；教育部及省级教育行政部门有细则（如[北京市实施细则](https://www.beijing.gov.cn/zhengce/zhengcefagui/202410/t20241029_3930108.html)） |
| 等保 2.0 | 进校采购/处理未成年人数据时可能被要求（二级起步） |
| 隐私与未成年人保护 | 隐私政策、最小化收集、家长同意、数据存储与删除机制 |
| 应用商店上架 | 软著、隐私政策、ICP、内容审核；教育类目需资质 |
| 内容审核 | 教学内容、史实表述、习题准确性 |

> 以上是产品化必须提前规划的成本项，**具体资质与流程以最新法规和平台规则为准**，启动前建议咨询合规顾问；不要把"能跑起来"误当成"能上线运营"。

### 4.5 成本与团队（粗略）

- 团队：1 全栈 + 1 前端/3D + 1 教研内容 = 3 人；MVP 2–3 个月。
- 固定成本：域名/服务器（数百元/月）、备案与等保（视要求，几千到数万元）、软著与上架材料、审核沟通时间。
- 运营成本：内容持续更新、客服、教师培训——这部分往往比开发更贵。

### 4.6 商业模式（可选）

- B 端：学校/机构按班级/年授权，含教师培训与私有化部署；
- C 端：知识点课程包订阅（先做单课程验证付费）；
- 出版/教具配套：书 + 3D 实验 + 二维码；
- 竞赛/研学：工作坊、师资培训。

### 4.7 主要风险

1. **政策与资质**：教育类审核、备案、未成年人保护是硬门槛。
2. **教学有效性**：3D 是否真的提升理解，需要前后测证据（这也是当前最值得先验证的）。
3. **同质化**：PhET、物理沙盒、各类 3D 教育产品已很多；差异化在"从器件到计算机的完整链路 + 可操作的物理仿真"。
4. **内容维护**：硬件/器件参数、史实、题目需要长期维护。

## 5. 推荐的推进阶梯（带决策门槛）

| 阶段 | 时间 | 做什么 | 通过门槛（进入下一阶段的条件） |
| --- | --- | --- | --- |
| **0 现在** | 已完成 | 桌面网页 + 手机布局 + APK + 设计文档 | — |
| **1 验证** | 2–4 周 | 给 10–20 位学生/老师试用；配 3 道前后测题；收集课堂录像/反馈 | 70% 教师愿意再用；学生前后测有提升趋势 |
| **2 轻量入口** | 1–2 个月 | PWA + 课堂包（二维码/教师手册/练习题）；小程序单场景 demo | 有 2+ 学校/机构愿意试用或付费意向 |
| **3 平台 MVP** | 3–6 个月 | 账号/班级/作业/学情；1–2 所学校试点；同步备案与合规 | 试点续费/扩班；留存与完成率达标 |
| **4 规模化** | 6–12 个月 | 多课程、多端、教师培训、渠道合作、VR/AR 探索 | 可持续收入模型 |

**核心建议：先用 APK/网页版把"教学效果"验证出来，再决定小程序和平台投入。** 目前缺的不是技术，而是"学生在哪些知识点上真的被 3D 帮到了"的证据。

## 6. 当前差距清单（离平台还差什么）

- 内容层：练习题与自动判分、教师手册、分层课程包、史实与参数校对；
- 产品层：账号体系、班级/作业、学情看板、分享与邀请、移动端细节打磨；
- 工程层：HTTPS 托管与发布流程、错误监控、性能分级（低端机降级）、无障碍；
- 合规层：备案、隐私政策、软著、上架素材；
- 运营层：教师培训、客服、内容更新节奏。
